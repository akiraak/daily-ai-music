# 音楽生成の仕組み(2026-08-06 決定)

会話で詰めた設計決定。実装プランは [docs/plans/music-generation-engine.md](../plans/music-generation-engine.md)。
**現在の実装の流れの図解は [music-generation-flow.md](music-generation-flow.md)**(この文書は決定の記録、あちらは挙動の説明)。

## 全体像

LLM(Claude API)がプリセット(要素プール)をもとに、毎回スタイルプロンプト+英語歌詞+日本語訳を生成し、Suno に `customMode: true` で渡す。生成に使ったプリセットをタスク単位で記録し、ユーザーの評価(👍/👎)はプリセット別の集計として次回生成のプロンプトに注入され、毎日良くなっていく(2026-08-08 変更: 当初の「好みプロファイル」文書方式を廃止し、評価の反映を使用プリセット×評価集計に一本化)。

```
評価(👍/👎) ────→ プリセット別 👍/👎 集計(task_presets × rating を毎回算出)
                        │
プリセット(DB) ──→ LLM(Sonnet 5)──→ スタイル + 英語歌詞 + 日本語訳 + タイトル + 使用プリセット
冒険日判定(20%) ─→                          │
                                customMode: true で Suno へ
                                            │
                              2 曲完成 → 1 曲目のみ data/ へ保存
```

## 決定事項

| 項目 | 決定 |
|---|---|
| プロンプトを組み立てる頭脳 | LLM(Claude API、`claude-sonnet-5`) |
| 歌詞 | LLM が英語で作詞し `customMode: true` で Suno に渡す。日本語訳も同時に生成し、両方保存 |
| 評価 | 曲ごとに 👍/👎 の 2 択。未評価は「普通」扱い(当初あった ★ お気に入りは 2026-08-07 に廃止、既存の ★ は 👍 に変換) |
| 評価の反映 | 使用プリセットをタスク単位で記録(`task_presets`)し、プリセット別の 👍/👎 を生成のたびに全期間集計して要素プール行に併記(👍 優先・👎 回避を指示。保存値なしのステートレス方式で、評価変更が次の生成に即反映)。2026-08-08 変更 — 当初の「好みプロファイル」文書を LLM が育てる方式は廃止(自由文書は妥当性を検証しにくく、データ+集計の方が挙動を追跡・制御しやすい。`profile` テーブルと過去データは履歴として残す) |
| プリセット | ジャンル・楽器・ムード・テンポ・歌声(2026-08-07 追加)を DB で管理し管理画面から編集。毎日の自動生成では全プールから LLM が評価を踏まえて自由に選ぶ。手動リクエスト時はユーザーが選択 |
| 歌声(2026-08-07 追加) | プリセットの `vocal` カテゴリで歌手の声の特徴(性別 × 声質 × 年齢感 + デュエット・聖歌隊等)を管理。歌詞ありの生成では style に歌声の特徴を必ず含め、直近と偏らないよう幅広い声色を試すよう LLM に指示する |
| ランダム要素 | 毎日「1 要素は普段と違うものを入れる」+ 確率 20%(設定変更可)で「冒険日」として大きく外す |
| 自動生成の量 | 1 日 1 リクエスト(12 クレジット)。Suno は 2 曲返すが同一歌詞・スタイルのバリエーションのため 1 曲目のみ採用(2026-08-07 変更。クレジット消費はリクエスト単位で不変) |
| 実行時刻 | 西海岸時間(America/Los_Angeles)朝 6:00。サーバー停止中に跨いだ場合は起動時に追い生成 |

## 生成フロー(毎日の自動生成)

1. スケジューラが PT 6:00 を検知(停止中に跨いだら起動時に追い生成)
2. 冒険日判定: 確率 20%(設定値)
3. **外部コンテキスト取得(2026-08-07 追加)**: ニュース(Google News RSS 日本版)・天気(Open-Meteo、位置は設定の緯度経度)を並行取得し「今日のコンテキスト」としてプロンプトに注入。取得失敗やソース OFF(設定画面で切替)ならセクション無しで続行し、生成は止めない。注入は毎日の自動生成のみ(手動リクエストは対象外)
4. **LLM コール(生成)**: 入力 = プリセット全プール(プリセット別の 👍/👎 集計を併記。2026-08-08 変更、旧: 好みプロファイル)+ 今日のコンテキスト + 直近数曲のスタイル(重複回避用)+ リアルワードの使用制限 + モード(通常/冒険)。出力(JSON) = スタイルプロンプト(英語)/タイトル/英語歌詞/日本語訳/使用プリセット(2026-08-08 追加 — 提示値をそのまま写す指示。サーバーで `presets` と照合して `task_presets` に保存し、不一致は警告ログのみ)/狙いの説明(日本語、管理画面表示用)/リアルワード(曲の中心となった語、英語小文字 5〜8 個)
5. Suno へ `customMode: true`(style / prompt=歌詞 / title / model)で送信
6. 完了検知〜音源保存は既存フローのまま。生成された 2 曲のうち 1 曲目のみ採用・保存する(2026-08-07 変更)。歌詞・訳・スタイル・狙いはタスク単位で保存

かつては生成の前に **LLM コール(プロファイル更新)** があったが 2026-08-08 に廃止(評価の反映をプリセット集計に一本化し、毎朝の LLM コールが 1 回減った)。

### リアルワードの使用制限(2026-08-07 追加)

似たテーマの曲の連続生成を防ぐ仕組み。全モード(daily / daily_adventure / manual)共通で `generateSongPlan` が一元処理する。

- 生成のたびに LLM が出力した `realWorldWords` を `real_world_words` テーブルへ保存(小文字正規化)
- 生成前に直近ウィンドウ(既定 30 日、`word_window_days`)の使用回数を集計し、上限(既定 2 回、`word_max_uses`)に達した語は「使用禁止ワード」、残り 1 回の語は「残り 1 回のワード」としてプロンプトに注入。ウィンドウを外れた語は自動的に再利用可能になる(物理削除なし)
- manual ではユーザーの選択・自由リクエストが禁止ワードより優先されると明記して注入する
- **検証リトライ**: 出力の realWorldWords に禁止ワードが残っていたら指示を強めて 1 回だけ再生成。それでも残る場合は警告ログのみで採用(生成を止めない)
- 使用状況は管理画面のパラメータ一覧ページ(リアルワード表)で確認できる

### 手動リクエスト

プリセットを選択(+自由テキスト)→ 同じ LLM 生成 → 同じ Suno フロー。手動生成の曲への評価も同じプリセット集計に反映される(使用プリセットはユーザー選択と LLM 出力の照合結果の和集合を記録)。ただし manual の生成プロンプトには評価集計を注入しない — ユーザー指定が最優先で、集計で誘導しない(2026-08-08)。

## データモデル(追加・変更)

- `tasks` に追加: `mode`('daily' | 'daily_adventure' | 'manual')、`style`、`style_ja`(スタイルの日本語訳。2026-08-07 追加)、`lyrics`(英語)、`lyrics_ja`、`title`、`intent`(LLM の狙い説明)、`llm_model`・`llm_prompt`(生成に使った LLM モデル名と入力全文。2026-08-07 追加、管理画面の楽曲詳細に生成パラメータとして表示)
- `tracks` に追加: `rating`(NULL / 1 / -1)
- `presets`(新規): `category`(genre / instrument / mood / tempo / vocal)、`value`(英語・プロンプト用)、`label_ja`(表示用)。初期セットはこちらで用意し、起動時に DB に 1 件も無いカテゴリだけ投入する(既存カテゴリ内の編集・削除は再投入で復活しない。vocal は 2026-08-07 追加)
- `profile`(新規 → 2026-08-08 廃止): プロファイル文書を版として積む方式だったが、更新・注入・閲覧の機能を削除。テーブルと過去データは履歴として残す
- `task_presets`(新規、2026-08-08): `task_id`、`preset_id`(集計用。参照強制なし)+使用時点のスナップショット `category` / `value` / `label_ja`(プリセットが編集・削除されても表示できる)。生成に使ったプリセットをタスク単位で記録し、`tracks.rating` との join で評価集計の元になる
- `settings`(新規): key-value(`adventure_probability`、`daily_enabled`、実行時刻・タイムゾーン等)。将来 iPhone から変更できるように DB 持ち。2026-08-07 追加: `context_news` / `context_weather`(外部ソース ON/OFF)、`weather_city` / `weather_lat` / `weather_lon`(天気の都市名と座標、既定は東京。設定画面では都道府県庁所在地のドロップダウンで選択し、都市名+座標を同時保存)、`word_max_uses` / `word_window_days`(リアルワード制限)。管理画面の設定ページ(/admin/settings.html)から変更でき、次の生成から即反映
- `real_world_words`(新規、2026-08-07): `task_id`、`word`、`created_at`。曲の中心となった語をタスク単位で記録し、使用回数制限の集計に使う

## API(追加)

- `POST /api/tracks/:id/rating` — 👍/👎 の付与・解除
- `GET/POST/PUT/DELETE /api/presets` — プリセット管理(2026-08-08: 各プリセットに評価集計 `upCount` / `downCount` を付与)
- ~~`GET /api/profile`~~ — 現行プロファイルの閲覧(2026-08-08 廃止)
- `GET/PUT /api/settings` — 設定(毎日の自動生成+外部コンテキスト+リアルワード制限)
- `GET /api/real-world-words` — 直近ウィンドウ内のリアルワード使用状況(パラメータ一覧ページ用)
- `POST /api/daily/run` — 自動生成の手動トリガ(検証・デバッグ用)
- `POST /api/generate` 拡張 — プリセット選択+自由テキストを受け、LLM 経由で生成

## コスト見込み

- Suno(kie.ai): 12 クレジット/日 ≈ 月 360 クレジット(数百円以下)
- Claude API(Sonnet 5): 1 コール/日、数円/日程度(2026-08-08 にプロファイル更新コールを廃止して 2 → 1 に)
- `.env` に `ANTHROPIC_API_KEY` を追加

## 補足

- Suno 連携の抽象化(`SunoClient`)は維持。`customMode` 対応で `GenerateParams` を拡張する
- 冒険日の曲も評価対象。👍 が付けばその要素の集計が上がり、以後の通常日に選ばれやすくなる(冒険日自体は評価集計に従わなくてよいと指示。2026-08-08 変更)
