# 生成した曲を表示する公開 Web を作る

作成: 2026-08-12

## 目的・背景

生成した曲は現在、認証付きの iOS アプリと管理画面(Cloudflare Access 保護の `/admin`)からしか聴けない。誰でも見られる公開ページを作り、Music Plant が毎日製造する曲を外に出す。

## Phase 0: 前提調査 — Suno 生成曲の著作権と公開可否(2026-08-12 実施済み)

### 1. 生成曲そのものに著作権はあるか → **原則「無い」**

- 日本法: 文化庁「AI と著作権に関する考え方について」(2024-03)の整理では、人間の創作的寄与がない AI 生成物は著作物に当たらない。プロンプト入力だけでは通常、創作的寄与とは認められない([文化庁 AI と著作権](https://www.bunka.go.jp/seisaku/chosakuken/aiandcopyright.html))
- 米国も同様(著作権局は人間の著作者性を要求)。Suno 自身も「100% AI 製の曲は著作権保護の対象にならない。プロンプトを書くことは曲の創作ではない」と明言している
- 帰結: **誰の著作物でもないので「公開を禁じる著作権」も基本的に無い**。裏返しに、自分が独占することもできない(他人の転載を著作権では止められない)

### 2. 規約上、公開してよいか → **非商用ならグレーだが実務リスクは低い**

- Suno 公式の規約: 無料プランは非商用のみ(生成物は Suno 帰属)。有料プラン(Pro/Premier)は商用利用可。ただし 2025-11 の Warner Music との和解・提携後、2025-12 の改定で「商用利用権があってもユーザーは曲の所有者とは見なされない」形に変更された([musicinafrica](https://musicinafrica.net/magazine/suno-adjusts-ai-music-ownership-terms-after-warner-music-partnership/) / [terms.law](https://terms.law/ai-output-rights/suno/) / [aismiley(日本語)](https://aismiley.co.jp/ai_news/suno-ai-music-generation-pro/))
- **本プロジェクトは Suno 公式ではなく kie.ai(非公式 API)経由**。kie.ai の [Terms of Use](https://kie.ai/terms-of-use)(2025-08-01 版)を全文確認したが、**生成物の権利・商用利用に関する条項が存在しない**([マーケティングページ](https://kie.ai/suno-api)で "Commercial use" を謳うのみ)。Suno のライセンスがエンドユーザーまで届く法的根拠は薄く、規約面はグレー
- Suno 自体が UMG・Sony と係争中(Warner とは 2025-11 に和解。2026-05 に原告が対象曲を 61,026 曲へ拡大申立、2026-07 に fair use のサマリージャッジメント審理。[ailawsuittracker](https://ailawsuittracker.com/cases/umg-v-suno/) / [dynamoi タイムライン](https://dynamoi.com/learn/ai-music-distribution/ai-music-copyright-cases-timeline))。サービス・規約の前提が今後変わり得る

### 3. 個別の曲のリスク → **参照曲ベース生成に固有のリスクがある**

- AI 生成物でも、既存曲への依拠性 + 類似性があれば公開・配信は著作権侵害になり得る(文化庁の整理でも同じ)。スタイル・作風の模倣自体は適法だが、メロディ・歌詞が既存曲に似すぎた出力は危ない
- 本プロジェクトは**参照曲に似せて作る方式なので構造的にこのリスクを持つ**(`properNounsIn()` による固有名詞チェックはあるが、音の類似は検知していない)

### 結論と公開の条件

**非商用の個人サイトとしての公開は進めてよい。** ただし:

1. **収益化しない**(広告・販売・ストリーミング配信・投げ銭など。やる場合はこの調査からやり直し)
2. **問題のある曲をすぐ非公開にできる手段を持つ**(→ 本プランの公開フラグ)
3. **公開ページに参照曲(実在アーティスト名・曲名)を出さない**(「その人の曲を元に作った」ことの対外的明示を避ける)
4. サイトに **AI 生成(Suno)である旨を明記**する(人間の作品との誤認防止)
5. 権利者から削除要請が来たら応じる

## 決定事項(2026-08-12 ユーザー確認済み)

- **公開範囲: 全曲公開 + 除外可(opt-out)**。生成された曲は自動で公開され、問題のある曲だけ後から非公開にできる
- **参照曲情報は公開ページに出さない**。曲名・カバー・再生・日付など生成物自体の情報のみ(スタイル文・歌詞・狙い・リアルワードも出さない。公開 API のレスポンス自体から落とす)
- **生成モデル名は表示する**(2026-08-12 追加指示)。`tasks.model`(Suno、例: V5_5)と `tasks.llm_model`(例: claude-sonnet-5)は曲ごとに保存済みで、iOS の楽曲詳細メタ情報でも表示している情報。AI 生成である旨の明記(調査結論の条件 4)を曲単位で裏付ける効果もある
- **デザインは案A(ギャラリー・ミニマル/ライト)を採用し、曲一覧+曲詳細の 2 ページ構成にする**(2026-08-12 目視確認で決定。案は下記「デザイン案」参照)

## 対応方針

同居の Hono サーバー(`server/src/index.ts`)に無認証の公開マウントを追加する。本番の Cloudflare Access は `/admin` だけを保護しているので、`/` 配下はそのまま外に出せる。

### DB(`server/src/db.ts`)

- `tracks.published INTEGER NOT NULL DEFAULT 1` を追加(opt-out なので既定 1 = 公開)。既存行も ALTER TABLE の DEFAULT で 1 になる
- `setTrackPublished(id, published)` と、公開曲のみを返す `listPublishedTracks()`、音源/画像ファイル名 → 公開判定のルックアップを追加

### ルーティング(`server/src/index.ts`)

- `GET /` のリダイレクト(`index.ts:764` の `c.redirect("/admin/")`)を撤去し、公開ページの静的配信に差し替える。静的ファイルは管理画面(`server/public/`)と分けて **`server/site/`** に置き、`/` にマウント(`/admin` は今まで通り)
- 公開 API・配信(すべて無認証。X-API-Secret ミドルウェアより前 or `/api` 外のパスに置く):
  - `GET /site/api/tracks` — 公開曲のみ。フィールドは `id` / `title` / `duration` / `createdAt` / `audioUrl` / `imageUrl` / `sunoModel` / `llmModel` に絞る(prompt・style・歌詞・参照曲・mode 等は**レスポンスに含めない**。ページ側で隠すだけでは不十分)
  - `GET /site/audio/:file`・`GET /site/images/:file` — **配信前に DB でそのファイルの曲が公開中か確認し、非公開・不明なら 404**(既存の `/api|/admin` の serveStatic 二重マウントは丸ごと配信なので流用せず、公開判定付きのハンドラを新設。Range 対応は既存の音源配信と同等に)
- 認証側 API に非公開化の口を追加: `PATCH /api/tracks/:id`(body `{ published: boolean }`)

### デザイン案(2026-08-12 作成 → 案A に決定)

実装前に 3 案のモックアップを `docs/plans/mockups/public-tracks-web/` に作成した(PC/モバイル両対応のレスポンシブ HTML。ローカルの実データ `data/images` `data/audio` を相対参照し、再生も動く)。閲覧はリポジトリ直下で `python3 -m http.server 8123` を起動して `http://localhost:8123/docs/plans/mockups/public-tracks-web/`(ビューア。モバイル幅 iframe + PC 表示リンク)。

- **案A ギャラリー・ミニマル(ライト)** `designA.html` — 白背景にカバーアートのグリッド(PC 4〜5 列 / モバイル 2 列)。ジャケット主役、日付・モデル名はカード下の小さなメタ表示 → **採用**
- 案B ファクトリー・ログ(ダーク)`designB.html` — 等幅フォント + LOT(日付)ごとの製造記録リスト → 不採用(参考として残置)
- 案C デイリー・プレイヤー(ダーク)`designC.html` — 最新曲ヒーロー + 下部固定プレイヤー → 不採用(参考として残置)

決定後、案A を **曲一覧(`designA.html`)+ 曲詳細(`designA-detail.html`)の 2 ページ構成**に拡張した。一覧はカードクリックで詳細へ遷移し、カバー上の ▶ ボタンだけ行内再生。詳細は大きいカバー + 曲名・日付・モデル名 + シークバー付きプレイヤー + 「ほかの曲」6 曲(回遊用)。モックアップは Phase 1 実装(`server/site/`)へ反映し、不要になった時点で削除する。

### 公開ページ(`server/site/`)

- 静的 HTML/CSS/JS の **2 ページ構成**(デザインは採用した案A。上記「デザイン案」参照)
  - **曲一覧**: 日付の新しい順のカバーアートグリッド(カバー・曲名・日付・時間・生成モデル名)。カードで詳細へ、カバー上の ▶ で行内再生。モデル名は `Suno V5.5 · claude-sonnet-5` のように小さく表示
  - **曲詳細**: 大きいカバー + 曲名・日付・モデル名 + シークバー付きプレイヤー + ほかの曲への導線。URL は曲 ID を含む(クエリ or パス。実装時に決定)
- フッターに「All songs are generated by AI (Suno) / このサイトの楽曲はすべて AI が生成したものです」の明記(調査結論の条件 4)
- 管理画面へのリンクは置かない(`/admin` の存在を公開ページから晒さない)
- サイト名は Music Plant。`<title>` と OGP 最小限

### 非公開化の操作 UI

- 管理画面の楽曲一覧(`server/public/index.html`)に公開/非公開トグルを追加
- iOS の楽曲詳細にも公開/非公開トグルを追加(opt-out 運用では「聴いてまずいと思ったらその場で下げる」が主動線なので iOS 側が重要)

## 影響範囲

- `server/src/db.ts` — tracks に published カラム + 操作関数
- `server/src/index.ts` — `/` リダイレクト撤去、`/site` 静的マウント、公開 API 3 本、`PATCH /api/tracks/:id`
- `server/site/`(新規)— 公開ページの静的ファイル
- `server/public/index.html`・`app.js` — 公開/非公開トグル
- `ios/` — 楽曲詳細に公開/非公開トグル(`BackendAPI` に PATCH 追加)
- 本番 — デプロイ後、`/` が Access 対象外で誰でも見えること・`/admin` は引き続き保護されていることを確認
- CLAUDE.md — 公開ページの節を追記

## テスト方針

- `npm run typecheck`
- 隔離 DB テストサーバー(sqlite3 .backup + `daily_enabled=false`、ポート 3014 以外)で:
  - `GET /site/api/tracks` が公開曲のみ・絞ったフィールドのみ返すこと(prompt / style / lyrics が漏れていないこと)
  - 非公開にした曲の `/site/audio/<file>` `/site/images/<file>` が 404 になること(URL 直叩き)
  - `/api/*` の認証が今まで通り効いていること(公開マウント追加で緩んでいないこと)
- 公開ページ・管理画面トグルはヘッドレス Chrome でスクリーンショット確認
- iOS はシミュレータビルド + トグルの手動確認
