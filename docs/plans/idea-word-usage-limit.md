# 生成に使ったアイデアワードを保存し、似た曲の連続生成を防ぐ

## 目的・背景

現在の重複回避は「直近 5 件のスタイル文字列を LLM に渡して『重複を避ける』と指示」するだけ
(`db.listRecentStyles`)で、ワード単位の管理が無く、似たテーマ・ジャンル・情景の曲が連続しやすい。
生成ごとに「使ったアイデアワード」を保存し、**直近ウィンドウ内で同じワードは 2 回まで**という
制限を掛ける。古いワードはウィンドウから外れて再び使えるようになる。

## 対応方針

### 仕組み

1. **ワードの抽出**: `SONG_PLAN_SCHEMA` に `keywords: string[]` を追加し、LLM 自身に
   「この曲で使った中心的なアイデアワード(テーマ・ジャンル・ムード・情景など)を
   英語小文字で 5〜8 個」出力させる(追加 LLM コールなし)
2. **保存**: 新テーブル `idea_words(id, task_id, word, created_at)` に保存
   (後方互換マイグレーション。既存タスクは対象外でよい)
3. **制限の注入**: 生成前にウィンドウ内(既定 30 日)のワードを集計し、プロンプトに追加:
   - 使用 2 回以上 → 「## 使用禁止ワード(直近で使いすぎ。テーマ・スタイル・歌詞の中心に据えない)」
   - 使用 1 回 → 「## 残り 1 回のワード(できれば別のアイデアを優先する)」
4. **期限切れ**: クエリを `created_at >= now - ウィンドウ` で絞るだけ(物理削除は不要。
   気になれば起動時にウィンドウ外を purge)。ウィンドウを外れたワードは自動的に再利用可能になる
5. **検証リトライ**: 返ってきた `keywords` に禁止ワードが含まれていたら、指示を強めて 1 回だけ
   再生成する(それでも含まれたら警告ログを出して採用 — 生成を止めない)

### 設定(settings テーブル。既定値でハードコード開始し、必要になったら UI 追加)

- `word_max_uses`: ウィンドウ内の同一ワード使用上限(既定 **2**)
- `word_window_days`: ウィンドウ日数(既定 **30**。毎日 1 曲+手動なので約 30〜40 曲分)

### 適用範囲

- daily / daily_adventure / manual の全モードに適用する(generateSongPlan 内で一元処理)。
  manual はユーザーの自由リクエスト・選択プリセットが最優先である旨を既存どおり維持し、
  ユーザー指定と禁止ワードが衝突した場合はユーザー指定を優先すると明記する
- 既存の `recentStyles`(直近 5 件のスタイル全文)は当面併用し、ワード制限が機能することを
  確認できたら削除を検討する

### Phase 構成

- **Phase 1: 保存** — スキーマ追加(`keywords`)、`idea_words` テーブル+マイグレーション、
  保存処理、管理画面の楽曲詳細に「使用ワード」を表示
- **Phase 2: 制限** — 集計+プロンプト注入+検証リトライ、設定キー
- **Phase 3: 可視化(任意)** — パラメータ一覧ページに「直近の使用ワードと残り回数」一覧を表示

### モデル精度の確認と Opus 5 への切替判断

現行 LLM は `claude-sonnet-5`(既定。$3/$15 per MTok)。Phase 1〜2 の稼働後に数日分の生成を
管理画面で確認し、keywords の質(曲の中心要素を的確に拾えているか)と禁止ワードの遵守率が
悪ければ `.env` の `LLM_MODEL` を **`claude-opus-5`**($5/$25 per MTok)へ変更する。

- どちらのモデルも構造化出力(`output_config.format` の json_schema)対応のためコード変更は不要
  (`llm.ts` は `LLM_MODEL` を参照、使用モデルは `tasks.llm_model` に記録済みで前後比較が可能)
- チェック観点: ① keywords が style / 歌詞の実内容と一致しているか ② 禁止ワード混入時の
  リトライ発生頻度(警告ログ)③ styleJa / lyricsJa の訳質

## 影響範囲

- `server/src/llm.ts`(スキーマ+セクション注入+リトライ)、`db.ts`(テーブル・集計クエリ)、
  `generation.ts`(keywords 保存)、`index.ts`(tasks/tracks API に keywords 追加)
- 管理画面(楽曲詳細・パラメータ一覧ページ)
- iOS は変更なし(API 追加フィールドは無視される)

## テスト方針

- 隔離 DB で保存・集計(2 回使用 → 禁止入り、ウィンドウ外 → 復活)の単体検証
- `npm run typecheck`
- E2E(実生成・クレジット消費)は Phase 2 完了時に 1 回実施し、llm_prompt に禁止ワード
  セクションが入ること・keywords が保存されることを確認

## 外部コンテキスト(ニュース・天気)プランとの関係

独立して実装可能。ニュース由来のテーマ語も keywords として記録されるため、
「同じ時事テーマが続く」ことへの抑制としても機能する。順序はどちらが先でもよい。
