# 調査: Suno で日本語の歌声が作れるか(2026-08-11)

## 目的・背景

現在の生成は **英語歌詞 + 日本語訳(表示用)** で固定されている(`server/src/llm.ts` の出力スキーマ: `lyrics` = 英語歌詞 / `lyricsJa` = その日本語訳)。
Suno に日本語を歌わせられるなら、参照曲が J-POP のときに「日本語で歌う曲」を作れる。まずは**可否と品質**を確かめる。

判断したいこと:

1. Suno(kie.ai 経由)は日本語歌詞を受け付けて、日本語で歌うか
2. 歌声・発音の品質は実用に耐えるか(どこが破綻するか)
3. 使うモデルは V5(現行)のままでよいか、V5_5 に上げるべきか
4. 本プロジェクトに適用する場合、どこを変えることになるか

## 調査方法

### Step 1: デスクリサーチ(完了)

Web 検索で「Suno + 日本語歌詞」の現状(対応可否・品質・表記の工夫・モデル差)と、kie.ai API のパラメータ(model の許容値・言語指定パラメータの有無)を確認する。

### Step 2: 実測(kie.ai で生成)

同一の日本語歌詞・同一の style を **V5 と V5_5 の 2 モデル**で生成して聴き比べる。

- 検証スクリプト: `scripts/verify-japanese-vocals.mjs`(既存の `verify-sunoapi.mjs` と同じ流儀 — 依存なし・`.env` 読み込み・ポーリング・MP3 を `output/` に保存)
- サーバー・DB は経由しない(タスク行を作らない単発スクリプト)
- 歌詞は**素の日本語**(漢字かな交じり・標準の表記)で書き、既知の罠を意図的に含める — 助詞「は」「へ」「を」/ 数字(七時・二人)/ 読み分けのある漢字(今日・明日・一日)
- 固有名詞は入れない(Suno のモデレーション対策。本体の `properNounsIn()` と同じ理由)
- 1 リクエスト = 2 曲 / 約 12 クレジット。2 モデルで計 4 曲・約 24 クレジット(残 540)

**歌声の自然さの最終判断は人間が聴いて行う**(こちらでは音声を評価できない)。スクリプトは MP3 を手元に落とすところまでを担当する。

## 影響範囲(適用する場合に触ることになる箇所 — 本調査のスコープ外)

- `server/src/llm.ts`: 出力スキーマ(`lyrics` / `lyricsJa` の意味)・`buildSongPlanPrompt()` の「出力条件」節・style への日本語ボーカル指定
- `server/src/config.ts`: `SUNO_MODEL`(V5 → V5_5)
- iOS / 管理画面: 歌詞の EN/JA 切り替え UI の前提(日本語が原詞になる場合の表示)
- `docs/specs/music-generation.md`: 歌詞言語の仕様

## テスト方針

- Step 2 のスクリプト実行が通ること(HTTP 200 → SUCCESS → MP3 4 本)
- 生成された MP3 を聴いて、日本語として歌えているか・どの語で破綻するかを記録する
- 本体(サーバー)のコードは変更しないので `npm run typecheck` 等の回帰確認は不要

## 結果

### Step 1: デスクリサーチ(2026-08-11)

- **日本語歌唱は可能**。Suno は 40〜50 言語に対応し、日本語もその中に入る。**API に言語パラメータは無く**、歌詞テキストの言語がそのまま歌われる(style に `Japanese vocals` / `natural Japanese pronunciation` を書いて補強するのが定石)
- kie.ai の `model` 許容値は **`V4` / `V4_5` / `V4_5PLUS` / `V4_5ALL` / `V5` / `V5_5`**。本プロジェクトは `V5` 固定(`server/src/config.ts` の `SUNO_MODEL`)。V5 / V5_5 は style 1000 文字・title 100 文字・prompt(歌詞)5000 文字まで
- **V5.5(2026-03-26 リリース)で漢字の読み精度が大きく改善**。「全部ひらがな」より「漢字かな交じりの自然な表記」の方が自然に歌う、という評価に変わった
- **残る弱点は 3 つ**(V5.5 でも解消していない) — ①助詞「は」「へ」を字面どおり読む ②数字を英語読みにする ③文脈依存の漢字の読み間違い(特に固有名詞・熟語)
- **回避策は表記の工夫**(コミュニティで確立している) — 助詞は「ワ」「エ」、「を」は「お」、数字はカタカナで音を書く(七時 → シチジ、二人 → フタリ)、読み間違える語だけカタカナ/ひらがなに置換。全部かなにするのは逆効果
- 料金はモデル間で差が無い(V5 と V5_5 で同額)

### Step 2: 実測(2026-08-11、kie.ai)

`node scripts/verify-japanese-vocals.mjs` を実行(V5 / V5_5 を並行)。

| | V5 | V5_5 |
|---|---|---|
| 受理 | ○(`SENSITIVE_WORD_ERROR` 無し) | ○ |
| 所要 | 108 秒 / 2 曲 | 124 秒 / 2 曲 |
| 出力 | 164s・140s | 158s・125s |
| ファイル | `output/ja-vocals/V5-{1,2}.mp3` | `output/ja-vocals/V5_5-{1,2}.mp3` |

- **日本語歌詞は customMode の `prompt` にそのまま渡して通る**。言語指定は不要で、モデレーションにも掛からない
- **`V5_5` は kie.ai で有効なモデル値**(本プロジェクトの現行値 `V5` から上げられる)
- 消費クレジット **24(1 リクエスト 12 × 2)**。V5 と V5_5 で同額。残 540 → 516
- 音源は 192kbps / 48kHz ステレオ(本体の生成物と同じ)。タイトルは日本語のまま(「はじまりの朝」)返る
- Suno 側の所要時間は英語と変わらない。本体の参照曲生成が 1 曲 3〜4.5 分なのは LLM の `web_search` 側であり、日本語化で伸びる要素は無い

**歌声の自然さは未判定**(音声は人間が聴いて評価する)。聴くときの観点 — 検証歌詞に仕込んだ罠:

| 罠 | 該当箇所 | 正しい読み |
|---|---|---|
| 助詞「は」 | 私は / 明日は | ワ |
| 助詞「へ」 | 街へ / 気持ちへ / 明日へ | エ |
| 助詞「を」 | 窓を / 夢を | オ |
| 数字 | 七時 / 二人 / 三分 / 一歩 | シチジ / フタリ / サンプン / イッポ |
| 読み分け | 今日 / 明日 / 一日 / 上っていく | キョウ / アシタ / イチニチ / ノボッテ |

再生: `afplay output/ja-vocals/V5-1.mp3`(`open output/ja-vocals/` でも可)
