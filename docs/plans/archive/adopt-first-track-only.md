# 曲生成は 2 曲のうち 1 曲目のみを採用する

## 目的・背景

Suno は 1 リクエストで通常 2 曲を返すが、同一歌詞・同一スタイルのバリエーションであり、一覧にほぼ同じ曲が 2 つ並ぶ。今後は 1 曲目のみを採用し、一覧をすっきりさせる。

- クレジット消費はリクエスト単位(12 クレジット)なので、1 曲だけ採用してもコストは変わらない
- 既存の保存済みトラックはそのまま残す(遡って削除しない)

## 対応方針

- `server/src/generation.ts` の `pollTask`: 完了検知時に `state.tracks` の先頭 1 件のみを `saveTracks` に渡す(`slice(0, 1)`)
  - 「1 曲目」= プロバイダのレスポンス `sunoData` 配列の先頭
  - 2 曲目はダウンロードも DB 登録もしない(プロバイダ側 URL は一時ファイルなので放置でよい)
  - ログに採用 1 件/受領件数を出す
- `docs/specs/music-generation.md` の 2 曲前提の記述(全体像の図・自動生成の量・生成フロー 7)を「2 曲生成されるが 1 曲目のみ採用」に更新

## 影響範囲

- `server/src/generation.ts` のみ(コード変更)
- API・DB スキーマ・管理画面・iOS は変更なし(トラック数が減るだけ)

## テスト方針

- `npm run typecheck`
- 実生成を伴うため自動テストは行わず、次回の生成(管理画面の生成ボタン or 毎日の自動生成)でトラックが 1 件のみ保存されることを確認する
